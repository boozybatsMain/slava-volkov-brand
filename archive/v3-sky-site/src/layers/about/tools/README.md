# about / tools — фотографии экрана ABOUT

Девять фотографий-обрывков экрана ABOUT (`public/assets/about/`). На референсе (`reference/about-screen.webp`) это рваные кусочки фото на чёрном: облака, листья, белая стена. Генератор даёт **чистые цветные фотографии во весь кадр**. Обесцвечивание, грейд, квантование, дизер, рваные края и зерно делает шейдер экрана. Поэтому в промптах нет рамок, виньетки и зерна, а в обработке нет грейда и резкости. Все девять файлов воспроизводятся скриптами из сырья в `$GEN_DIR` (по умолчанию `./.gen-work`, в git не попадает).

| файл | назначение |
|---|---|
| `generate.sh` | точные промпты девяти картинок. `generate.sh [<name>…]` генерирует их параллельно через `../../sky-layers/tools/gen.sh … opaque`, без аргументов — все девять (бюджет генераций исчерпан, см. ниже). `DRY=1` только печатает промпты |
| `process.py` | сырьё → `public/assets/about/*.webp` + контакт-лист `shots/v4-about/assets/sheet.png`; в консоль — размер, KB, качество и яркость каждой картинки |

```sh
# из корня проекта
DRY=1 src/layers/about/tools/generate.sh                                     # все промпты, без генерации
GEN_DIR=$PWD/.gen-work src/layers/about/tools/generate.sh                    # все девять параллельно, ≈2–3 мин, тратит лимит подписки
GEN_DIR=$PWD/.gen-work src/layers/about/tools/generate.sh about-place        # одна картинка
python3 src/layers/about/tools/process.py                                    # 9 картинок + контакт-лист, ≈20 с
python3 src/layers/about/tools/process.py --only about-place --out /tmp/x --shots /tmp/x/s   # проба в сторону
```

Генерации не детерминированы. Если `.gen-work` потерян, повторный запуск даст другие картинки, и описания и цифры ниже придётся обновить. Обработка детерминирована: повторный прогон в пустую папку (`--out`, `--shots`) даёт все девять WebP и `sheet.png` байт-в-байт (проверено после генераций 8–9).

- **`about-canopy` — 1152, а не 1280.** Мелкая листва плохо жмётся: на 1280 даже q 70 даёт 246 KB. Поэтому `process.py` после качества понижает размер шагами по 64 px; влезло на 1152×768 q 70 (217 706 байт). Остальные восемь — 1280 по длинной стороне (квадраты остались 1024: апскейла нет) на q 77–86; `about-cirrus` и `about-succulent` влезли сразу на q 86.
- **Без окна.** `CROP` в `process.py` пуст: всё сырьё взято целиком, и каждое окно на экране вырезает свой кусок через `crop` в конфиге. Одна картинка может кормить несколько окон: например, из `about-place` отдельно окошко, отдельно лестница, из `about-clouds-a` — отдельные клочки, из `about-succulent` — домашний обрывок и полутоновое окно в t4.
- **Цвет.** Палитра чуть прохладная и приглушённая, кроме листьев: у `about-leaves-a` насыщенность 71, тёплая жёлто-зелёная. Экран всё равно обесцвечивает, но если `grade` окна оставляет цвет, листьям нужно больше `saturation` вниз, чем остальным. Второе по насыщенности — голубое небо `about-cirrus` (55); `about-succulent` почти серый (21).

## Генерации и выбор

**9 генераций Codex из 9 разрешённых — бюджет исчерпан.** Первые семь — одним прогоном. Две последние (`about-cirrus`, `about-succulent`) — отдельным заходом после второго ревью: оно нашло, что коллаж повторяет одни и те же кадры (окошко стены второй раз в t2, крона и дома, и в финале), и попросило светлое небо и бледное растение. Все девять взяты с первой попытки, отклонённых нет, повторов не было. Каждая проверена глазами и цифрами: нет текста и водяных знаков, нет рамки (скачка яркости у краёв нет ни у одной: ≤ 6 уровней, и это сам кадр; у двух новых ≤ 3), нет виньетки (углы темнее центра только там, где этого требует сюжет — у кроны просветы к центру, у облаков синее небо по углам; у суккулента углы светлее центра). Сюжет совпадает с промптом.

- Обёртка — `../../sky-layers/tools/gen.sh <name> <size> opaque "<prompt>"`. В начало она ставит `Use your built-in image generation tool (not code) to create exactly ONE image, size <size>, highest quality.`, в конец — `Full-frame opaque image. No text, no watermark, no people, no birds, no airplanes. Save the resulting PNG …`. Строка «no people / no birds» хамелеону не мешает.
- Промпты — ровно те, что получил генератор: `DRY=1 src/layers/about/tools/generate.sh` (в файле — общий хвост `STYLE` и по абзацу на картинку; композиция задана долями кадра).
- Сырьё 1536×1024 и 1024×1536 пришло ровно этого размера. **`about-leaves-a`, `about-chameleon` и `about-succulent` генератор отдал 1254×1254**, и Codex сам уменьшил их до заказанных 1024×1024 через `sips -z` (видно в `run.log`). Это только уменьшение, без апскейла: качество не страдает. Но если сырьё понадобится крупнее, его исходник лежит в `~/.codex/generated_images/…`, путь — в `run.log`.
- Параллельный прогон первых семи занял ≈ 3 мин (20:13 → 20:16), двух новых — ≈ 1.5 мин (23:50 → 23:51).

## Как заменить картинку

1. **Новая генерация.** Поправить промпт в `generate.sh` и запустить `GEN_DIR=$PWD/.gen-work src/layers/about/tools/generate.sh <name>`. Старое сырьё перезапишется; если оно может пригодиться, сначала переименуйте папку `.gen-work/<name>`. Одна генерация ≈ 1.5–3 мин и тратит лимит подписки ChatGPT. Разрешённые 9 генераций уже потрачены: новую нужно согласовать заранее. fal не использовать: для клиента дорого.
   **Своя фотография** (например, настоящая от клиента) — положить PNG в `.gen-work/<name>/<name>.png`. Если размер отличается от `RAW[<name>]` в `process.py`, поправить `RAW`: другой размер скрипт считает ошибкой, чтобы не взять чужое сырьё.
2. Если в кадре есть лишнее (поля, подпись), задать окно в `CROP[<name>]` в `process.py`, px сырья `(x0, y0, x1, y1)`.
3. Запустить `python3 src/layers/about/tools/process.py --only <name>` и посмотреть `shots/v4-about/assets/sheet.png`. Контакт-лист собирается по всем готовым WebP, не только по пересчитанным.
4. Проверить `crop` и `grade` окон, которые берут эту картинку (конфиг экрана ABOUT): числа подобраны под нынешние кадры. Обновить таблицы выше: файл, KB, яркость, что в кадре, генерации.

Имя файла можно оставить тем же, тогда конфиг трогать не нужно. Новое имя нужно добавить в `RAW` (`process.py`), `NAMES` / `SIZE` / `PRM` (`generate.sh`) и в конфиг.
